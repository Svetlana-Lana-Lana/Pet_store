## О проекте

В данном проекте выполнен ряд заданий по исследованию API сайта https://petstore.swagger.io/. 
Сайт является демонстрационным API для тестирования и изучения работы с REST-сервисами через Swagger UI, а также через Postman.

## Задание 1. Написать описание проекта по документации в общем виде. Как авторизоваться, какие сущности есть.

Проект представляет собой магазин домашних животных.

Авторизация осуществляется одним из двух способов:
- ввод api-key в header;
- получение токена доступа в браузере (OAuth2).

**Базовый URL: https://petstore.swagger.io/v2** 

В проекте есть следующие сущности: **домашнее животное, магазин, пользователь**.

## Задание 2. Описать одну сущность на выбор, указав какие действия над ней можно проводить, ориентируясь на запросы.

Действия, которые можно осуществить в отношении сущности «Домашнее животное»:
- добавить домашнее животное в магазин;
- загрузить изображение ранее добавленного домашнего животного;
- обновить информацию о ранее добавленном домашнем животном (ID передается в теле запроса);
- поиск домашних животных по статусу;
- поиск конкретного домашнего животного по его ID;
- обновить информацию о домашнем животном в некоторых полях через форму (ID передается в URL);
- удаление домашнего животного из магазина.

## Задание 3. Описать один запрос из выбранной сущности, а именно как отправляется информация, какие есть ключи, какие типы и за что отвечают эти ключи.

Обновление информации о домашнем животном

Запрос: PUT /pet Update an existing pet

Метод запроса – PUT

URL запроса https://petstore.swagger.io/v2/pet 

В запросе обязательно должно присутствовать тело – json. При отправке запроса информация о животном полностью заменяется телом PUT запроса. 

Json может включать в себя следующие ключи:
- Id – идентификационный номер домашнего животного, присваиваемый животному при добавлении в магазин, тип данных – integer;
- category – объект, включает в себя ключи: 
  - id – идентификационный номер категории, тип данных – integer;
  - name – название категории, тип данных string;
- name – имя домашнего животного, тип данных – string;
- photoUrls – веб-адрес изображения животного, возможно добавлять более одного адреса, тип данных – массив строк;
- tags – добавление тэгов к информации о домашнем животном, возможно добавление более одного тэга, тип данных – массив объектов. Каждый объект массива включает в себя ключи:
  - id – идентификационный номер тэга, тип данных – integer;
  - name – название тэга, тип данных string;
- status – отображает информацию о доступности домашнего животного к приобретению.

В соответствии с документацией обязательными являются ключи name  и photoUrls.

В ответе приходит json с обновленной информацией о домашнем животном.

## Задание 4. Работа с запросами через Swagger. Отправить корректные запросы на 5 разных эндпоинтов. Объяснить какая информация отправляется и какую получаем. Приложить скрины выполненных запросов.

### 1 запрос

Вывод списка домашних животных, отфильтрованных по статусу.

GET https://petstore.swagger.io/v2/pet/findByStatus 

Значение статуса передается в URL запроса. Можно указать несколько значений статуса, разделённых запятыми.

Доступны три статуса: available, pending, sold.

В ответе приходит список объектов (модель PET) – домашних животных с искомым статусом.

Возможные коды ответов:
- 200 – в случае успешного запроса;
- 400 – в случае неверного значения статуса.

![get_findByStatus](https://github.com/Svetlana-Lana-Lana/Pet_store/blob/main/screenshots/get_findByStatus.png)

### 2 запрос

Вывод списка статусов домашних животных с количеством по каждому статусу.

GET https://petstore.swagger.io/v2/store/inventory 

В запросе передается только указанный выше URL.

В ответе приходит объект, ключи которого являются названиями статусов доступности домашних животных к заказу. Значения ключей – количество животных в статусе. Тип данных - integer.

Возможные коды ответов:
- 200 – в случае успешного запроса.

![get_inventory](https://github.com/Svetlana-Lana-Lana/Pet_store/blob/main/screenshots/get_inventory.png)

### 3 запрос

Создание пользователя

POST https://petstore.swagger.io/v2/user 

В теле запроса передается json, ключами которого является информация о создаваемом пользователе.

В ответе приходит объект с ключами: code - код ответа, type – строка с текстом "unknown", message – строка с присвоенным пользователю id.

Возможные коды ответов:
- 200 – в случае успешного запроса. 

![createUser](https://github.com/Svetlana-Lana-Lana/Pet_store/blob/main/screenshots/post_createUser.png)

### 4 запрос

Авторизация пользователя в системе

GET https://petstore.swagger.io/v2/user/login

Значения логина и пароля передаются в URL запроса.

Параметры логин и пароль являются обязательными для авторизации.

В ответе приходит объект с ключами: code - код ответа, type – строка с текстом "unknown", message – строка с уведомлением об авторизации "logged in user session:1778837962190".

Возможные коды ответов:
- 200 – в случае успешного запроса;
- 400 – в случае ошибочных данных в параметрах имя пользователя и/или пароль.

![login](https://github.com/Svetlana-Lana-Lana/Pet_store/blob/main/screenshots/get_login.png)

### 5 запрос

Размещение заказа в магазине.

POST https://petstore.swagger.io/v2/store/order

В теле запроса передается json, ключами которого является информация о пользователе и выбранном домашнем животном.

В ответе приходит json с информацией о заказе.

Возможные коды ответов:
- 200 – в случае успешного запроса; 
- 400 – в случае ошибочных данных в заказе.

![makeAnOrder](https://github.com/Svetlana-Lana-Lana/Pet_store/blob/main/screenshots/post_makeAnOrder.png)
